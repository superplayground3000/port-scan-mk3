# 2.0.0 Release Notes

## Summary

`port-scan` is now a **three-step pipeline** instead of one monolithic `scan`
command. The two expensive pre-phases — reachability pinging and bucket/chunk
conversion — are split into their own separately-runnable subcommands with
visible progress, so a long run can be staged, observed, and resumed at
well-defined boundaries:

1. **`preping`** — ping every unique target IP and write the
   `unreachable_results-<ts>.csv` blocklist. Prints the resolved path to stdout
   for chaining.
2. **`generate-buckets`** — read the targets (minus an optional unreachable
   blocklist), build the per-CIDR chunk set in parallel, and write a resume
   **bucket snapshot** (the existing resume JSON) to `-buckets-out`.
3. **`scan`** — a pure TCP scanner that consumes a bucket snapshot via
   `-resume` (now **required**). It never pings and never builds chunks.

Each arrow between steps is a durable file, so the pipeline can stop and restart
at any boundary. `rich.csv` (`-cidr-file`) is threaded into all three steps
because it is the single source of truth for target metadata.

## Breaking changes

This is a **MAJOR** release because the `scan` command contract changed in a
backward-incompatible way.

- **`scan` now requires `-resume <bucket file>`.** It no longer accepts raw
  input for an end-to-end run; it scans only the buckets in the snapshot
  produced by `generate-buckets`. Running `scan` without `-resume` exits with
  code `2` and the message `-resume is required`.
- **`scan` no longer pings.** The reachability checker is not constructed on the
  scan path at all — "scan never pings" now holds *by construction*, not by a
  flag. Reachability filtering comes entirely from the blocklist embedded in the
  bucket snapshot.
- **Ping flags removed from `scan`.** `-disable-pre-scan-ping` and
  `-pre-scan-ping-timeout` are no longer registered for `scan`; passing either
  is now an unknown-flag error (exit `2`). Pinging is controlled by whether you
  run the `preping` step at all — to skip pinging, skip `preping` and call
  `generate-buckets` with no `-unreachable-file`.
- **`scan` no longer writes `unreachable_results-*.csv`.** That artifact is now
  produced by `preping`.

## Flag relocation

Every flag from the old monolithic `scan` is preserved; it has moved to the step
that owns it. New flags are marked **NEW**.

| Flag | Old home | New home | Notes |
|------|----------|----------|-------|
| `-cidr-file` (req) | `scan` | `preping`, `generate-buckets`, `scan` | Threaded into all three steps. |
| `-cidr-ip-col` / `-cidr-ip-cidr-col` | `scan` | `preping`, `generate-buckets`, `scan` | Column mapping, shared. |
| `-workers` | `scan` | `preping`, `generate-buckets`, `scan` | Also parallelizes bucket generation. |
| `-log-level` / `-format` / `-quiet` | `scan` | `preping`, `generate-buckets`, `scan` | Shared observability flags. |
| `-pre-scan-ping-timeout` | `scan` | `preping` only | Removed from `scan`. |
| `-disable-pre-scan-ping` | `scan` | **removed** | Skip pinging by skipping the `preping` step. |
| `-port-file` | `scan` (req in basic mode) | `generate-buckets` (primary); `scan` (fallback, normally ignored) | Bucket chunks carry ports; basic-mode `scan` still falls back to it if the snapshot has none. |
| `-output` | `scan` | `preping` (unreachable CSV dir/anchor); `scan` (scan/opened CSV dir/anchor) | `generate-buckets` uses `-buckets-out` instead. |
| `-timeout` / `-delay` / `-bucket-rate` / `-bucket-capacity` | `scan` | `scan` only | Scan-only dial/dispatch tuning. |
| `-disable-api`, `-pressure-*` (all pressure-API flags) | `scan` | `scan` only | Pressure control is scan-only. |
| `-resume` | `scan` (optional) | `scan` only (**now required**) | Reads and writes the bucket snapshot. |
| `-unreachable-file` | — | **NEW** — `generate-buckets` only (optional) | Blocklist to subtract; the `preping` output. |
| `-buckets-out` | — | **NEW** — `generate-buckets` only (**required**) | Bucket snapshot output path. |
| `-progress-interval` | — | **NEW** — `preping`, `generate-buckets`, `scan` | Progress line cadence (count of processed units); default `100`. |

## Migration

The old single command:

```bash
# before (1.x)
port-scan scan -cidr-file rich.csv -port-file ports.txt -output out/
```

becomes the three steps below. `preping` prints its resolved
`unreachable_results-<ts>.csv` path to stdout — capture it and pass it to
`generate-buckets` as `-unreachable-file`:

```bash
# after (2.0.0)
UNREACHABLE=$(port-scan preping -cidr-file rich.csv -output out/)

port-scan generate-buckets -cidr-file rich.csv -port-file ports.txt \
                           -unreachable-file "$UNREACHABLE" \
                           -buckets-out out/buckets.json

port-scan scan -cidr-file rich.csv -resume out/buckets.json -output out/
```

Notes:

- **Skipping the ping step** (the old `-disable-pre-scan-ping=true`): just omit
  `preping` and call `generate-buckets` without `-unreachable-file`. The
  snapshot then covers all targets and still stamps `pre_scan_ping.enabled=true`,
  so `scan` never pings.
- **Basic-mode inputs** still need `-port-file` on `generate-buckets` (the ports
  live in the chunks). Rich-mode inputs carry their per-target port and need no
  `-port-file`.
- **The `-unreachable-file` filename is timestamped and non-deterministic**, so
  chaining requires capturing `preping`'s printed path (the `$UNREACHABLE`
  capture above), not hard-coding a name.
- On interrupt (`SIGINT`) or error, `scan` updates the resume snapshot **in
  place at the `-resume` path** — a cancelled scan overwrites the bucket file it
  read, now carrying progress. Re-running the same `scan` command continues from
  there.

## Compatibility notes

- **CSV schemas and file naming are unchanged.** The rich/basic input contracts,
  the 12-column `unreachable_results-<ts>.csv` header, and the
  `scan_results-<ts>.csv` / `opened_results-<ts>.csv` batch outputs are all
  byte-identical to 1.x. Rich/basic auto-detection is unchanged.
- **The bucket file is the existing resume `Snapshot` JSON.** A snapshot
  produced by `generate-buckets` is shape-identical to one written by an
  interrupted legacy run (`{chunks, pre_scan_ping}`), so `pkg/state` needs no
  reader change. The "unreachable results are finalized before any TCP dial"
  guarantee is now enforced by **CLI sequencing** — `preping` is a separate step
  that completes before `scan` runs — rather than by ordering inside a single
  command.
- **Removed convenience path:** there is no "run all three at once" wrapper. The
  split intentionally removes the monolithic path; chaining the three steps is
  the caller's job (shell/pipeline).

## Versioning note

Product version is release-notes-and-git-tag based: the build stamps its version
from `git describe` via `-ldflags` (`Makefile`), and there is no hardcoded
version constant in `cmd/` to edit. This `2.0.0` release note (the next MAJOR
after `1.4.0`) is the version-of-record; tag the release `v2.0.0` at merge.
