# 4.0.0 Release Notes — Smaller Go Interfaces

## Summary

Version 4.0.0 replaces the shared configuration object with workflow-specific
values. It also moves HTTP and OAuth pressure adapters to `pkg/pressure`.

This release corrects an authorization error in rich input. A `decision=deny` row can no longer reach an ICMP or TCP probe.

This release adds two target expansion flags. Output schemas and exit classes stay compatible.

New snapshots include `rich_deny_excluded` and `target_expansion`. Current and legacy snapshot files remain readable.

## Target expansion limits

- The default candidate limit is `10000000`.
- The default target expansion budget is `16` decimal GB.
- The estimate is `1000000000 + candidate count * 1500` bytes.
- `-target-count-limit N` replaces the count limit.
- `-target-memory-limit-gb N` replaces the memory limit.
- A value of `0` disables its limit. A negative value is an error.
- All commands stop before network probes and output creation when a limit fails.
- `validate` calculates the estimate without target enumeration.
- `generate-buckets` stores the effective limits and candidate count.
- `scan` counts only incomplete chunks and uses stored limits by default.

CAUTION: If both limits are `0`, target expansion has no hidden limit.
The process can stop when the host or operating system cannot supply more resources.

This release changes the public Go interface for library callers.

## Authorization correction

- A rich deny row produces no network target.
- A deny row overrides an accept row with the same normalized `execution_key`.
- The rule applies before ICMP, bucket generation, resume rebuild, and TCP dispatch.
- A deny-only input writes an empty snapshot and header-only result files.
- A deny-only scan reports zero tasks and exits with code `0`.
- `validate` continues to reject malformed deny rows.
- `scan` rejects an unmarked snapshot with rich deny input before TCP dispatch.
- If this legacy snapshot error occurs, run `generate-buckets` again.

## Breaking Go API changes

- Use `config.ParsePrePing`, `config.ParseGenerateBuckets`, `config.ParseScan`,
  or `config.ParseValidate` for command arguments.
- Use `config.NewPrePing`, `config.NewGenerateBuckets`, `config.NewScan`, or
  `config.NewValidate` for values from another source.
- Pass each opaque configuration to its matching workflow. The workflow owns
  the narrow configuration interface.
- `scanapp.RunOptions` now exposes `Dial`, `PressureLimit`,
  `DisableKeyboard`, `PressureSource`, `ProgressInterval`, and
  `ReachabilityChecker`.
- `RunOptions.ResumeStatePath` is removed. Put the snapshot path in
  `config.ScanValues.ResumeInput`.
- `RunOptions.PressureFetcher` and `RunOptions.PressureHTTP` are removed.
  `RunOptions.PressureSource` is the replacement seam.
- `config.Config`, `config.Parse`, and `config.ParseFor` are removed.
- `scanapp.ScanRecord` and the public writer adapters are removed. Runtime code
  uses `writer.Record` directly.
- `PressureFetcher`, `SimplePressureFetcher`,
  `AuthenticatedPressureFetcher`, and `MultiSourcePressureFetcher` are removed.
- The old pressure fetcher constructors are removed. Use
  `pressure.NewSimpleHTTP` or `pressure.NewOAuthMulti` for a custom pressure
  source.

## Migration examples

Replace shared argument parsing with the parser for the selected workflow:

```go
cfg, err := config.ParseScan(args)
if err != nil {
    return err
}
return scanapp.Run(ctx, cfg, stdout, stderr, scanapp.RunOptions{})
```

For non-CLI scan values, construct a validated pressure policy first:

```go
policy, err := config.SimplePressure("https://router.example/pressure", 5*time.Second)
if err != nil {
    return err
}

cfg, err := config.NewScan(config.ScanValues{
    CIDRFile:       "targets.csv",
    CIDRIPCol:      "ip",
    CIDRIPCidrCol:  "ip_cidr",
    ResumeInput:    "buckets.json",
    Output:         "out",
    Workers:        10,
    DialTimeout:    100 * time.Millisecond,
    DispatchDelay:  10 * time.Millisecond,
    BucketRate:     100,
    BucketCapacity: 100,
    LogLevel:       "info",
    Format:         "human",
    Pressure:       policy,
})
if err != nil {
    return err
}
return scanapp.Run(ctx, cfg, stdout, stderr, scanapp.RunOptions{})
```

For an injected pressure source, implement the consumer-owned interface:

```go
type source interface {
    Sample(context.Context) (pressure.Sample, error)
}

opts := scanapp.RunOptions{PressureSource: mySource}
```

The explicit local `source` declaration is optional. A value with the same
`Sample` method satisfies `scanapp.PressureSource`.

## Performance evidence

This release adds a private, cross-platform large-data harness for `port-scan`.
The harness uses production parsing, bucket, resume, scan, and writer paths.

Run `make verify-performance` for the complete native Linux matrix.
Linux and Windows CI run bounded 100,000-record and 100 MB smoke cases.

Each report includes one cold run and a five-run steady-state median.
The report also includes fixture manifests, correctness checks, metrics, thresholds, and hardware details.

The harness does not certify the scale budgets of issue 151.
Read [`../performance-harness.md`](../performance-harness.md) for commands and report fields.

## Compatibility

- Existing CLI invocations do not need migration.
- Current and legacy snapshots remain readable.
- New snapshots record `rich_deny_excluded=true`.
- New snapshots record target expansion limits and the pre-filter candidate count.
- The CSV and unreachable-result schemas do not change.
- `validate` still accepts and verifies the complete legacy flag set.

## Cancellation safety

- The first Ctrl+C or Windows Ctrl+Break starts graceful cancellation.
- Input parsing, runtime rebuild, dispatch waits, and queue sends stop.
- Queued probes do not start. Started probes finish with their original timeout.
- The command writes late in-flight results before snapshot persistence.
- The snapshot rewinds each chunk to its lowest unwritten task.
- A resumed run can repeat a row. It cannot skip an unwritten task.
- The second Ctrl+C or Ctrl+Break forces exit code `130` immediately.
- A snapshot-save error returns exit code `1` and reports prior snapshot usability.

## Rollback and mitigation

CAUTION: Version 3.0.1 can scan a rich deny row. Do not roll back a rich
workflow that contains deny rows.

Version 3.0.1 remains suitable for other CLI rollback cases. Do not reuse a
4.0.0 snapshot after rollback. The older strict decoder rejects the
`rich_deny_excluded` field. Create a new snapshot with the rollback version.

A Go application that rolls back must also restore its old `config.Config`
and pressure-fetcher calls.

If an application cannot migrate in one change, isolate its version-specific
calls behind a small application-owned adapter. Do not pass partially verified
values to a workflow.
