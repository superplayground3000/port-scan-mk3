# 4.0.0 Release Notes — Smaller Go Interfaces

## Summary

Version 4.0.0 replaces the shared configuration object with workflow-specific
values. It also moves HTTP and OAuth pressure adapters to `pkg/pressure`.

This release narrows the values that `--fab-name` accepts. Commands, default
values, output schemas, exit classes, and snapshot formats stay compatible.
This release changes the public Go API for library callers.

## Breaking CLI change — narrowed `--fab-name` values

`preprocess` rejects eight fab names that version 3.0.1 accepted. The fab name
becomes a directory name in the output tree, so a stored command can stop with
exit code `1` after the upgrade.

The eight added names are `CONIN$`, `CONOUT$`, `COM¹`, `COM²`, `COM³`, `LPT¹`,
`LPT²`, and `LPT³`. Windows reserves each one for a device.

- Version 3.0.1 already rejected `CON`, `PRN`, `AUX`, `NUL`, `COM0` through
  `COM9`, and `LPT0` through `LPT9`. That part does not change.
- The match ignores letter case, so `conin$` and `CONIN$` both fail.
- The match uses the stem of the name. It removes an extension and trailing
  spaces and dots, so `com¹.txt` and `com¹ ` also fail.
- The match rule itself is unchanged from version 3.0.1. Only the set of
  reserved names is larger.
- Every other fab name that version 3.0.1 accepted still works.
- `preprocess` checks the name before it reads the input files.

The command reports the rejection as `--fab-name: invalid fab name "conin$":
"conin$" is a name Windows reserves for a device`.

**Migration:** if a stored command now stops with `invalid fab name`, choose a
fab name that is not a Windows device name. The fab name selects the output
directory, so the new name creates a new directory.

## Breaking Go API changes

- Use `config.ParsePrePing`, `config.ParseGenerateBuckets`, `config.ParseScan`,
  or `config.ParseValidate` for command arguments.
- Use `config.NewPrePing`, `config.NewGenerateBuckets`, `config.NewScan`, or
  `config.NewValidate` for values from another source.
- Pass each opaque configuration to its matching workflow. The workflow owns
  the narrow configuration interface.
- `scanapp.RunOptions` now exposes `Dial`, `PressureLimit`,
  `DisableKeyboard`, `PressureSource`, `ProgressInterval`, and
  `ReachabilityChecker`.
- `RunOptions.ResumeStatePath` is removed. Put the snapshot path in
  `config.ScanValues.ResumeInput`.
- `RunOptions.PressureFetcher` and `RunOptions.PressureHTTP` are removed.
  `RunOptions.PressureSource` is the replacement seam.
- `config.Config`, `config.Parse`, and `config.ParseFor` are removed.
- `scanapp.ScanRecord` and the public writer adapters are removed. Runtime code
  uses `writer.Record` directly.
- `PressureFetcher`, `SimplePressureFetcher`,
  `AuthenticatedPressureFetcher`, and `MultiSourcePressureFetcher` are removed.
- The old pressure fetcher constructors are removed. Use
  `pressure.NewSimpleHTTP` or `pressure.NewOAuthMulti` for a custom pressure
  source.

## Migration examples

Replace shared argument parsing with the parser for the selected workflow:

```go
cfg, err := config.ParseScan(args)
if err != nil {
    return err
}
return scanapp.Run(ctx, cfg, stdout, stderr, scanapp.RunOptions{})
```

For non-CLI scan values, construct a validated pressure policy first:

```go
policy, err := config.SimplePressure("https://router.example/pressure", 5*time.Second)
if err != nil {
    return err
}

cfg, err := config.NewScan(config.ScanValues{
    CIDRFile:       "targets.csv",
    CIDRIPCol:      "ip",
    CIDRIPCidrCol:  "ip_cidr",
    ResumeInput:    "buckets.json",
    Output:         "out",
    Workers:        10,
    DialTimeout:    100 * time.Millisecond,
    DispatchDelay:  10 * time.Millisecond,
    BucketRate:     100,
    BucketCapacity: 100,
    LogLevel:       "info",
    Format:         "human",
    Pressure:       policy,
})
if err != nil {
    return err
}
return scanapp.Run(ctx, cfg, stdout, stderr, scanapp.RunOptions{})
```

For an injected pressure source, implement the consumer-owned interface:

```go
type source interface {
    Sample(context.Context) (pressure.Sample, error)
}

opts := scanapp.RunOptions{PressureSource: mySource}
```

The explicit local `source` declaration is optional. A value with the same
`Sample` method satisfies `scanapp.PressureSource`.

## Compatibility

- Existing CLI invocations do not need migration. The one exception is a
  `preprocess` command whose `--fab-name` is one of the eight newly reserved
  names.
- Current and legacy snapshots remain readable.
- The CSV and unreachable-result schemas do not change.
- `validate` still accepts and verifies the complete legacy flag set.

## Rollback and mitigation

Version 3.0.1 remains suitable for CLI rollback. The CSV and snapshot contracts
are unchanged, and version 3.0.1 accepts every fab name that version 4.0.0
accepts. A Go application that rolls back must also restore its old
`config.Config` and pressure-fetcher calls.

If an application cannot migrate in one change, isolate its version-specific
calls behind a small application-owned adapter. Do not pass partially verified
values to a workflow.
