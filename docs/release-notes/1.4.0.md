# 1.4.0 Release Notes

## Changes
- Broadcast addresses are no longer scanned. When targets are built, the broadcast
  address of each row's boundary subnet (`ip_cidr` in basic mode,
  `dst_network_segment` in rich mode) is excluded. The exclusion is
  boundary-relative and applies whether the address came from CIDR expansion or
  was listed explicitly as a single IP:
  - `10.0.0.0/24` scans `10.0.0.0`–`10.0.0.254` (broadcast `10.0.0.255` dropped).
  - An explicit `10.0.0.255` with boundary `10.0.0.0/24` is dropped.
  - `10.0.0.255` with boundary `10.0.0.0/23` is kept — it is a valid host, not the
    `/23` broadcast (`10.0.1.255`).
  - The network address (all host bits clear) is retained.
  - `/31` (RFC 3021) and `/32` boundaries have no broadcast and are unchanged.

## Compatibility notes
- Behavior change: any scan whose targets previously included a subnet broadcast
  will now scan one fewer host per affected subnet. Output row counts drop
  accordingly.
- Resume compatibility: a resume state file written by a pre-1.4.0 build carries
  the old (broadcast-inclusive) `total_count`. Resuming it with 1.4.0 in a path
  that reuses saved chunks (`-disable-pre-scan-ping`, a saved pre-scan-ping state,
  or a run where the pre-scan filters no hosts) now fails fast with an actionable
  message: the resume state is incompatible with the current target set — start a
  fresh scan (remove `-resume` or delete the resume file). Same-version resume is
  unaffected. This is intentional: the target set genuinely changed, so silently
  reconciling it could mask a real input change.
