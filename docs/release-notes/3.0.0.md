# 3.0.0 Release Notes — The Reachability Step Is Named `pre-ping`

## Summary

The first step of the pipeline is renamed from `preping` to `pre-ping`
(issue #97). The old name read as one word and was easy to confuse with the
`-pre-scan-ping-timeout` flag that the same step owns. The new name uses the
same hyphenated style as the other two steps, `generate-buckets` and `scan`.

This is a **MAJOR** release, because the rename is a breaking CLI change. There
is no alias: `port-scan preping` is now an unknown command.

Nothing else changes. The flags, the outputs, the CSV schemas, the resume
snapshot format and the exit codes are the same as in 2.2.0.

## Breaking changes

- **The subcommand is `pre-ping`.** Run `port-scan pre-ping [flags]`. The flag
  surface of the step is unchanged.
- **`preping` is not accepted and is not an alias.** It takes the standard
  unknown-command path: `port-scan` writes `unknown command: preping` to stderr
  and exits with code `2`. A script that still uses the old name fails loudly at
  the first step; it does not scan with a different behavior.
- **The progress label on stderr is `pre-ping`.** The step now prints lines like
  `pre-ping: 12/40 (30.0%)`. A tool that greps stderr for `preping:` must be
  updated.
- **The Go entry point is `scanapp.RunPrePing`.** The former `scanapp.RunPreping`
  no longer exists. This affects callers that import `pkg/scanapp` directly.

## Migration

Change the subcommand token in every script, Makefile, CI job and container
invocation. No flag, path or output name changes.

```bash
# before (2.x)
UNREACHABLE=$(port-scan preping -cidr-file rich.csv -output out/)

# after (3.0.0)
UNREACHABLE=$(port-scan pre-ping -cidr-file rich.csv -output out/)
```

The rest of the pipeline is unchanged:

```bash
port-scan generate-buckets -cidr-file rich.csv -port-file ports.txt \
                           -unreachable-file "$UNREACHABLE" \
                           -buckets-out out/buckets.json

port-scan scan -cidr-file rich.csv -resume out/buckets.json -output out/
```

Notes:

- To find every call site, search your automation for the token `preping`. The
  step still prints its `unreachable_results-<ts>.csv` path to stdout, so a
  script that captures that path keeps working after the token is changed.
- Go callers rename `scanapp.RunPreping` to `scanapp.RunPrePing`. The signature
  and the behavior are the same.
- To skip the reachability check, skip the `pre-ping` step and call
  `generate-buckets` without `-unreachable-file`. This is unchanged from 2.0.0.

## Compatibility

### Unchanged

- **No flag is added, removed or renamed.** `pre-ping` owns `-cidr-file`,
  `-cidr-ip-col`, `-cidr-ip-cidr-col`, `-workers`, `-progress-interval`,
  `-output`, `-pre-scan-ping-timeout`, `-log-level`, `-format` and `-quiet`,
  exactly as `preping` did.
- **The `-pre-scan-ping-timeout` flag keeps its name.** That name was already
  unambiguous and is not part of this rename.
- **No output changes.** The `unreachable_results-<ts>.csv` name and its
  12-column header are byte-identical to 2.x, as are the `scan_results-<ts>.csv`
  and `opened_results-<ts>.csv` outputs.
- **No resume-state change.** A bucket snapshot written by 2.x is read by 3.0.0
  without conversion, and the reverse is also true.
- **Exit codes are unchanged** for the step itself: parse error `2`, interrupt
  `130`, any other error `1`, success `0`.

### Rollback

Revert the commit that carries this rename, or install the previous 2.x binary.
No on-disk format is involved, so a rollback needs no data migration: snapshots
and CSV files written by 3.0.0 are readable by 2.x. After a rollback, scripts
must use the `preping` token again, because 2.x does not accept `pre-ping`.

Because the two names never coexist, do not mix a 2.x binary and a 3.0.0 binary
in one automated pipeline.

## Versioning note

The product version comes from the release notes and the git tag: the build
stamps its version from `git describe` through `-ldflags` in the `Makefile`, and
no hardcoded version constant exists in `cmd/`. This `3.0.0` note is the
version-of-record; tag the release `v3.0.0` at merge, with an annotated tag
(`git tag -a v3.0.0 -m "..."`), as required since 2.2.0.

## Verification

Gate evidence for this release:

- `make verify` exits `0` (gofmt, `go vet`, build, `go test -race -shuffle=on`,
  and the >=85% coverage gate).
- `make verify-e2e` exits `0`. The isolated Docker e2e runs the three steps
  (`pre-ping` -> `generate-buckets` -> `scan`) in sequence against mock services
  and asserts open, closed and timeout detection, with artifacts in `e2e/out/`.
- `TestRunMain_PrePing_CommandContract` in `cmd/port-scan` pins both halves of
  the contract: `pre-ping` dispatches to the pre-ping runner and writes the
  unreachable CSV, and the 2.x token exits `2` with an unknown-command message.
