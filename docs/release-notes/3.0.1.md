# 3.0.1 Release Notes — Preserve Progress After an Output-Write Failure

## Summary

This release preserves safe scan progress after an output-write failure
(issue #57). Version 2.1.1 prevented silent data loss by saving no new resume
state after this failure. That safe fallback forced the next run to repeat all
work from the prior snapshot.

Version 3.0.1 saves a corrected snapshot instead. It rewinds each affected
chunk to its first dispatched task that did not reach all required output
writers. The resumed run covers every target and can write duplicate rows.

## Fixes

- Each internal scan task and result carries its zero-based chunk task index.
- The result loop records each dispatched result that was not fully persisted.
- The snapshot save rewinds only affected chunk cursors.
- If all dispatched results were persisted, the chunk keeps its cursor.
- A rewind sets `ScannedCount` to the corrected `NextIndex`.
- The structured `resume_state_rewound` event records the save path and affected
  chunk count.
- The failed run still exits with the original output-write error.

Results can finish out of order. Therefore, a rewind can repeat rows that were
persisted after an earlier task. This duplicate-row behavior is intentional.
It is safer than skipping a row that never reached an output file.

## Recovery

Run the same `scan -resume <snapshot>` command after you correct the output
failure. The command appends results from the corrected cursor to the recorded
`scan_results-*.csv` and `opened_results-*.csv` files.

If duplicates are not acceptable, process each output file with a CSV parser.
Do not use line-based tools because quoted CSV fields can contain newlines.

The script below keeps the last row for each TCP target. It uses `ip` and
`port` as the task identity. Run it separately for each output file.

```python
# dedupe_scan_csv.py
import csv
import sys

source_path, output_path = sys.argv[1:3]

with open(source_path, newline="", encoding="utf-8") as source:
    reader = csv.DictReader(source)
    if reader.fieldnames is None:
        raise SystemExit("input CSV has no header")
    fieldnames = reader.fieldnames
    latest_rows = {}
    for row in reader:
        latest_rows[(row["ip"], row["port"])] = row

with open(output_path, "w", newline="", encoding="utf-8") as output:
    writer = csv.DictWriter(output, fieldnames=fieldnames)
    writer.writeheader()
    writer.writerows(latest_rows.values())
```

```bash
python3 dedupe_scan_csv.py scan_results-<timestamp>.csv scan_results-deduped.csv
python3 dedupe_scan_csv.py opened_results-<timestamp>.csv opened_results-deduped.csv
```

## Compatibility and migration

- No CLI flag changes.
- No output CSV schema changes.
- No resume snapshot schema changes.
- Snapshots from 3.0.0 remain readable.
- Graceful interruption keeps exact resume behavior with no missing or
  duplicate rows.
- Hard-crash recovery for `SIGKILL` or power loss is unchanged.

No migration is necessary. A rollback to 3.0.0 restores the older behavior.
That version discards new progress after an output-write failure.
